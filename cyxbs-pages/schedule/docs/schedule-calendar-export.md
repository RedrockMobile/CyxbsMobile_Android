# Schedule 系统日历投影

## 1. 当前边界

Android 与 iOS 当前都只把 Schedule 单向投影到系统日历。系统日历不是日程事实源，用户在系统日历中的修改不会回写服务端 Schedule。

受管日历名称为“掌邮日程”。Android 通过 Calendar Provider，iOS 通过 EventKit；两端都必须按应用所有权标记识别事件，不能覆盖或删除用户自己创建的同名事件。

代码中的 `CalendarOccurrenceException` 指系统日历 Provider/EventKit 对重复事件例外的原生概念，不是 Schedule 业务模型。业务层统一使用 `OccurrenceAdjustment`，两者只在投影边界进行转换。

## 2. 投影规则

| Schedule 状态 | 系统日历 |
| --- | --- |
| `TIMED` | 普通开始/结束事件 |
| `DEADLINE` | `DTSTART == DTEND` 的零时长事件 |
| `ALL_DAY` | 单日全天，使用排他结束边界 |
| `UNSCHEDULED` | 不导出 |
| TODO 已完成 | 不导出；恢复未完成后重新建立 |
| AFFAIR 关联清单后完成 | 仍按事务来源保留投影 |
| `linkedToCourse=false` 且无提醒 | 不导出 |

提醒只有一条。`minutesBefore=0` 写为准时提醒；正数表示提前分钟数。没有明确日期/时间的旧清单即使含历史提醒值也不写入系统日历。

重复 Schedule 投影为主事件；`CANCELLED` 或不应单独展示的 occurrence 状态投影为对应原始实例的原生例外。单次标题、时间等业务调整在支持的适配器边界写入同一实例。

## 3. 权限

用户第一次开启提醒时先展示“日程提醒借助手机系统日历实现”的说明，再请求平台权限。拒绝或系统未授权时，本次编辑回到不提醒。

其他设备同步来的提醒在当前设备未授权时仍保留服务端字段，信息区显示“准时（未授权）”或“提前 X 分钟（未授权）”。非编辑态也可点击并重新进入授权流程。

Android 已永久拒绝时，由 Android 平台实现弹出说明并跳转应用设置；这一判断不下沉到 commonMain。

## 4. 对账与覆盖

进入日程能力、账号切换或仓库发布新快照时，对当前账号受管日历进行对账：

```text
读取本地 Schedule 投影
  -> 读取受管日历和应用拥有的事件
  -> 按稳定事件 URI/所有权标记匹配
  -> 新建缺失事件
  -> 更新应用拥有且内容变化的事件
  -> 删除不再需要的应用拥有事件
  -> 忽略所有权不匹配的行
```

应用卸载重装后，稳定账号和 Schedule identity 仍可重新识别应用创建的行。若 Provider 中存在无法解析的旧格式行，对账不能永久卡住：只忽略非所有权行，对明确属于当前应用和账号的旧行允许重建。

## 5. 账号隔离

所有权标记必须包含稳定账号摘要和 Schedule identity。切换账号后只操作新账号对应的受管事件；旧账号事件保留在其日历中，直到该账号再次进入并按自身远端状态对账。
